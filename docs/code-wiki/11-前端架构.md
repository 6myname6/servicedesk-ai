# 11 · 前端架构

## 1. 技术栈与工程化

| 项 | 选型 |
| --- | --- |
| 框架 | Vue 3.5（`<script setup>` 组合式 API） |
| 构建 | Vite 6 |
| 状态 | Pinia 3 |
| 路由 | Vue Router 4（history 模式） |
| UI | Element Plus 2.9 + 全量图标注册，中文 locale |
| HTTP | Axios 1.7 |
| 包管理 | npm |

### 1.1 启动入口

`frontend/src/main.js`：

```js
const app = createApp(App)
Object.entries(ElementPlusIconsVue).forEach(([name, c]) => app.component(name, c)) // 图标全量注册
app.use(createPinia())
app.use(router)
app.use(ElementPlus, { locale: zhCn })
app.mount('#app')
```

### 1.2 Vite 配置

`frontend/vite.config.js`：

| 配置 | 说明 |
| --- | --- |
| `@` 别名 | 指向 `src` |
| `server.host/port` | `127.0.0.1:5173` |
| `server.proxy` | `/api` → `http://127.0.0.1:8080`，保留前缀 |
| `build.outDir` | `dist` |
| `manualChunks` | `vendor-element`（Element Plus + 图标）、`vendor-vue`（Vue/Router/Pinia/Axios） |

前端代码只写相对路径 `/api`，不出现后端地址；生产环境由 nginx 反代做到同样效果。

### 3.2 全局守卫

`router.beforeEach`：

```mermaid
flowchart TB
    A[导航到 to] --> B{meta.public?}
    B -- 是 --> C{已登录且访问 login/register?}
    C -- 是 --> D[回 /dashboard]
    C -- 否 --> E[放行]
    B -- 否 --> F{有 token?}
    F -- 否 --> G[/login?redirect=to.fullPath]
    F -- 是 --> H{store.user 存在?}
    H -- 否 --> I[loadMe 拉 /auth/me]
    I -->|失败| J[clear + 回登录]
    I -->|成功| K{meta.roles 匹配?}
    H -- 是 --> K
    K -- 否 --> L[/403]
    K -- 是 --> E
```

`router.afterEach` 设置 `document.title = "{标题} · 智维工单"`。

前端角色守卫只做**入口级控制**，真正的数据范围由后端裁剪。

## 4. 状态管理

`stores/auth.js`（Pinia option store）：

| 状态 / Getter | 说明 |
| --- | --- |
| `token` | 初始化自 `localStorage['sd_token']` |
| `user` | 初始化自 `localStorage['sd_user']`，缓存用于刷新时避免白屏 |
| `isLoggedIn` | `Boolean(token)` |
| `role` / `roleLabel` | 当前角色编码 / 中文名 |
| `isAdmin` | `role === 'ADMIN'` |
| `canManageAssets` | `SUPERVISOR` 或 `ADMIN` |

| Action | 行为 |
| --- | --- |
| `login(payload)` | 调登录接口 → 写 token / user → 写 localStorage |
| `loadMe()` | 调 `/auth/me` 校正缓存 |
| `logout()` | 先调后端登出（拉黑 token），`finally` 清本地 |
| `clear()` | 清空 store 与 localStorage |

## 5. HTTP 层

`api/http.js`：

| 能力 | 实现 |
| --- | --- |
| 基址 | `baseURL: '/api'`，超时 20s |
| 请求拦截 | 从 `localStorage` 取 token，注入 `Authorization: Bearer` |
| 业务失败 | 响应体 `code !== 200` → `Promise.reject(Error{code, message})` |
| 成功返回 | 直接返回 `body.data`，页面不感知包装结构 |
| 401 处理 | 派发 `window` 自定义事件 `sd:unauthorized`，由根组件统一清状态并跳登录 |
| 错误提示 | 非 `silent` 请求用 `ElMessage.error` 展示后端 message 或状态码兜底文案 |
| 特殊标记 | `skipAuthRedirect`、`silent` |

兜底文案映射：400 / 401 / 403 / 404 / 409 / 413 / 429 / 500 / 503。

`App.vue` 监听 `sd:unauthorized`：清空登录态并 `router.replace('/login?redirect=...')`。HTTP 层不直接依赖 store / router，避免循环依赖。

### 10.1 原型数据的约定

`src/mock/prototype.js`：

- 时间字段按后端序列化格式 `yyyy-MM-ddTHH:mm:ss`；
- 以「当前时间 + 偏移分钟」构造，保证 SLA 倒计时与时间线在任意日期打开都合理；
- 后端接口就绪后删除该文件，页面改为调用 `src/api/` 下真实接口。

### 10.2 已知边界

| 边界 | 原因 |
| --- | --- |
| 客户 / 设备下拉仅主管与管理员可用 | 后端客户档案查询限 `SUPERVISOR` / `ADMIN`；报修人 / 工程师建单需填客户 ID |

| 详情页未接真实接口 | 接口已就绪，前端尚未切换 |

## 11. 构建与部署

```bash
cd frontend
npm install
npm run dev      # 5173，/api 代理到 8080
npm run build    # dist/
npm run preview  # 本地预览 dist
```

产物：`index.html` + `assets/`（`vendor-vue`、`vendor-element` 单独拆包，便于 nginx 长期缓存）。

nginx 部署见 [13 构建运行与部署](./13-构建运行与部署.md)。要点：

- `location /api/` 的 `proxy_pass` 不带 URI，否则 `/api` 前缀会被吃掉；
- history 路由需要 `try_files $uri $uri/ /index.html`；
- `index.html` 不缓存，`/assets/` 长期缓存。
