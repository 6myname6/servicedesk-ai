# 14 · 测试体系

## 1. 测试分层

| 类型 | 技术 | 数量 | 特点 |
| --- | --- | --- | --- |
| Mockito 单元测试 | JUnit 5 + `@ExtendWith(MockitoExtension.class)` | 3 | 不启动 Spring，mock 依赖，验证纯逻辑 |
| Spring 集成测试 | `@SpringBootTest`（控制器用例另加 `@AutoConfigureMockMvc`） | 24 | 启动完整上下文，使用真实 MySQL / Redis |
| 纯 JUnit 测试 | JUnit 5 | 9 | 枚举、领域规则、JWT、上下文等无外部依赖逻辑 |

> 统计口径：`backend/src/test/java` 下共 **36 个测试类**。

## 2. 测试环境要求

集成测试**不是纯内存测试**：

- 需要本地 MySQL 8，且已执行 `backend/sql/V1` ~ `V10`；
- 需要本地 Redis 7，且密码与 `application.yml` 一致；
- 部分用例会写 `ticket:seq:*` 等 Redis key，在 `@AfterEach` 手工清理；
- 数据库用例使用 `@Transactional`，方法结束自动回滚，避免污染。

若只想跑纯单元测试，可指定少量类，例如：

```bash
cd backend
mvn test -Dtest='OssFileStorageServiceTest,TicketScopeResolverTest,FileAttachmentServiceImplTest'
```

## 5. 运行方式

```bash
cd backend

# 全部测试
mvn test

# 单个类
mvn test -Dtest=TicketControllerTest

# 单个方法
mvn test -Dtest=TicketControllerTest#shouldCreateTicket

# 跳过测试打包
mvn clean package -DskipTests
```

测试报告：`backend/target/surefire-reports/`。

## 6. 测试编写约定

1. **类名** `<被测类>Test`，包路径与被测类一致或对应分层；
2. **每个类有 Javadoc**，说明测试层级（单元 / 集成）与重点覆盖的风险；
3. **`@DisplayName` 用中文**描述业务场景；
4. **集成测试自建数据**，依赖 `@Transactional` 回滚；Redis 等非事务副作用在 `@AfterEach` 清理；
5. **不 mock 数据库**：Controller 测试走真实 MySQL，确保 SQL、索引、分页插件真实生效；
6. **存储层测试不触网**：OSS 用 Mockito / `@MockitoBean` 替换；
7. **固定时间**：涉及 SLA / 工单号的用例优先用 `Clock.fixed` 或注入可控 `Clock`；
8. **断言重点**：状态码、`code`、关键字段、事件条数、数据库副作用。

## 7. 测试覆盖缺口

| 缺口 | 说明 | 建议 |
| --- | --- | --- |
| 登录限流的并发窗口 | 当前覆盖串行计数 | 增加并发压测或 Lua 边界用例 |
| 多实例 SLA 扫描并发 | 条件更新逻辑已覆盖单实例 | 增加并行事务模拟 |
| 工单号降级多实例撞号 | 单元测试覆盖单路径 | 增加并发降级用例 |
| 前端 | 无自动化测试 | 引入 Vitest / Playwright |
| AI / 知识库 / 报表 | 无实现，无测试 | 落地时补契约测试 |
| 安全扫描 | 无依赖漏洞扫描 | 接入 OWASP Dependency-Check |
| 性能 | 无基准测试 | 对列表、时间线、超时扫描做基准 |

## 8. 与 CI 的衔接建议

当前仓库没有 CI 配置。若接入流水线，建议顺序：

```
1. mvn -q -DskipTests package        # 编译
2. 启动 MySQL / Redis 服务容器
3. 执行 V1~V10 迁移
4. mvn test                           # 集成测试
5. npm ci && npm run build            # 前端构建
6. （可选）部署到 nginx 并跑冒烟脚本
```

注意：集成测试依赖真实数据库，CI 中需要用 service container 或本地安装，不能只靠 H2。
