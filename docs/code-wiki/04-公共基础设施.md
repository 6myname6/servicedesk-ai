# 04 · 公共基础设施

本文件覆盖 `com.servicedesk.common` 包，以及所有业务都会用到的 DTO / VO 约定。这些东西不承载业务语义，但决定了全项目的接口风格与错误风格。

## 1. 统一响应体 `Result<T>`

位置：`backend/src/main/java/com/servicedesk/common/api/Result.java`

```java
public final class Result<T> {
    private final int code;      // 与 HTTP 状态码一致，200 成功
    private final String message; // 可直接展示给用户的中文文案
    private final T data;        // 无数据时为 null
}
```

| 静态方法 | 用途 | 示例 |
| --- | --- | --- |
| `success(T data)` | 带数据成功 | `Result.success(ticketDetailVO)` |
| `success()` | 无数据成功 | 删除、登出、改密 |
| `error(int code, String message)` | 失败，仅供全局异常处理器调用 | `Result.error(404, "工单不存在")` |

前端约定：只要 `code !== 200` 就按失败处理；`code` 同时用于区分「重新登录（401）」「无权限（403）」「刷新重试（409）」。

## 2. 统一分页 `PageResult<T>`

位置：`common/api/PageResult.java`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `records` | `List<T>` | 当前页数据，不会是 null |
| `total` | `long` | 满足条件的总记录数 |
| `curPage` | `long` | 当前页码，从 1 开始 |
| `pageSize` | `long` | 每页条数 |
| `pages` | `long` | 总页数 |

两个工厂方法：

- `PageResult.from(IPage<T>)`：不转换元素；
- `PageResult.from(IPage<T>, Function<T,R>)`：边转换边分页，实体 → VO 场景使用。

**刻意不直接暴露 MyBatis-Plus 的 `IPage`**，避免把 `orders`、`optimizeCountSql`、`searchCount` 等实现细节写进接口契约。

## 3. 业务异常与全局异常处理

### 3.1 `BusinessException`

```java
throw new BusinessException(404, "工单不存在");
```

- `code` 与 HTTP 状态码一致；
- 只允许面向用户的中文提示，不允许堆栈、SQL、内部标识；
- 资源不存在与越权统一 404，避免调用方枚举资源。

### 3.2 `GlobalExceptionHandler`

位置：`common/exception/GlobalExceptionHandler.java`，`@RestControllerAdvice`。

| 异常类型 | HTTP / code | 响应 message |
| --- | --- | --- |
| `BusinessException` | `ex.getCode()` | `ex.getMessage()` |
| `BindException`（含 `MethodArgumentNotValidException`） | 400 | `字段: 提示；字段: 提示` |
| `ConstraintViolationException` | 400 | 约束消息 |
| `MissingServletRequestParameterException` | 400 | `缺少必填参数: xxx` |
| `MethodArgumentTypeMismatchException` | 400 | `参数格式不正确: xxx` |
| `HttpMessageNotReadableException` | 400 | `请求体格式不正确` |
| `MissingServletRequestPartException` | 400 | `缺少必填参数: xxx` |
| `MaxUploadSizeExceededException` | 413 | `文件大小超过限制` |
| `MultipartException`（沿 cause 链判断超限） | 413 / 400 | 超限 413，否则「上传请求格式不正确」 |
| 其他 `Exception` | 500 | `服务端错误`（堆栈只进日志） |

处理顺序上的一个细节：`MethodArgumentNotValidException` 是 `BindException` 的子类，因此只声明父类即可接住 `@RequestBody @Valid` 与查询对象 `@Valid` 两种场景。

## 4. 登录用户上下文

### 4.1 `LoginUser`（不可变快照）

```java
public record LoginUser(Long id, String username, String displayName, String role, Long teamId) {}
```

只放鉴权与数据范围必需的最小字段，不放密码、手机号等敏感信息。

### 4.2 `UserContext`（ThreadLocal）

| 方法 | 行为 |
| --- | --- |
| `set(LoginUser)` | 写入当前线程 |
| `get()` | 读取，可能为 null |
| `getRequired()` | 读取，为 null 抛 401「未登录或登录已过期」 |
| `getUserId()` | `getRequired().id()` |
| `clear()` | 移除当前线程值 |

**生命周期**：`AuthInterceptor#preHandle` 写入 → 业务层读取 → `AuthInterceptor#afterCompletion` 清理。Tomcat 线程池会复用线程，不清理会导致身份串号（严重越权缺陷）。

## 5. 配置类

### 5.1 `WebMvcConfig`

- 注册 `AuthInterceptor`，`order(1)`，`/**`，排除白名单；
- 注册 `RoleInterceptor`，`order(2)`，同样的路径与白名单；
- 白名单常量：

```text
/auth/login, /v3/api-docs/**, /swagger-ui/**, /swagger-ui.html, /actuator/**, /error
```

注意路径不含 `/api`：`server.servlet.context-path` 在进入 `DispatcherServlet` 前已被剥离。

### 5.2 `MybatisPlusConfig`

```java
interceptor.addInnerInterceptor(new OptimisticLockerInnerInterceptor());
interceptor.addInnerInterceptor(paginationInnerInterceptor()); // MAX_LIMIT = 100
```

- 分页插件 `DbType.MYSQL`，单页最大 100 条，`overflow=false`（页码越界不重算）；
- 乐观锁插件配合实体上的 `@Version`，更新时自动拼 `WHERE version = ?` 并自增。

### 5.3 `TimeConfig`

```java
@Bean
public Clock clock() {
    return Clock.system(ZoneId.of("Asia/Shanghai"));
}
```

约定：业务取「今天 / 现在」一律注入 `Clock`，不直接 `LocalDate.now()`。原因：

1. 单测可用 `Clock.fixed(...)` 模拟跨天、时钟回拨；
2. 避免集群内 JVM 时区不一致导致同一天出现两种日期段；
3. 与 `spring.jackson.time-zone`、JDBC `serverTimezone` 保持同一口径。

### 5.4 `OpenApiConfig`

- 标题「智维工单 ServiceDesk AI」，版本 `1.0.0`；
- 声明全局 `bearerAuth`（HTTP Bearer / JWT）；
- Swagger UI：`/api/swagger-ui.html`；OpenAPI JSON：`/api/v3/api-docs`；
- 扫描包：`com.servicedesk.controller`。

## 6. Redis 原子计数器 `RedisAtomicCounter`

位置：`common/utils/RedisAtomicCounter.java`

```java
public long incrWithTtl(String key, long ttlSeconds)
```

Lua 脚本一次性完成：

```lua
local count = redis.call('INCR', KEYS[1])
if count == 1 then
    redis.call('EXPIRE', KEYS[1], ARGV[1])
end
return count
```

设计要点：

- **固定窗口**：TTL 只在 key 首次创建时设置，后续自增不续期，窗口到期计数自动归零；
- **不感知业务**：key 命名空间、窗口长度由调用方决定；
- **不参与数据库事务**：DB 回滚不会退计数。

使用方：

| 调用方 | Key | TTL |
| --- | --- | --- |
| `LoginRateLimiter` | `auth:loginFail:user:{username}` / `auth:loginFail:ip:{ip}` | 300 秒 |
| `TicketNoGenerator` | `ticket:seq:{yyyyMMdd}` | 2 天 |

## 7. 请求 DTO 一览

所有请求 DTO 位于 `com.servicedesk.dto.request`，使用 Lombok `@Data` + Bean Validation。**只做格式校验**，存在性、唯一性、状态合法性由 Service 判断。

### 7.1 认证

| 类 | 字段 | 校验 |
| --- | --- | --- |
| `LoginRequest` | `username`、`password` | 用户名 3-32；密码 8-32 |
| `ChangePasswordRequest` | `oldPassword`、`newPassword` | 原密码必填；新密码 8-32；新旧不能相同（业务层） |

### 7.2 工单

| 类 | 字段 | 校验 / 说明 |
| --- | --- | --- |
| `TicketCreateRequest` | `title`、`description`、`customerId`、`deviceId`、`category`、`urgency`、`imageUrls` | 标题 ≤128 必填；描述 ≤5000 必填；客户必填；分类 ≤16 缺省 OTHER；紧急度 ≤8 缺省 P2；附件 ≤5，每个 URL ≤512 |
| `TicketUpdateRequest` | `title`、`description`、`category`、`urgency`、`deviceId`、`version` | 业务字段均可选；`version` 必填且 ≥0 |
| `TicketQueryRequest` | `keyword`、`status`、`urgency`、`category`、`assigneeId`、`teamId`、`mine`、`escalated`、`page`、`size` | 状态 / 紧急度 / 分类传了就必须合法；`page≥1`；`size` 1-100 |

| `TicketAssignRequest` | `assigneeId`、`comment`、`version` | 工程师必填；备注 ≤255；版本必填 |

| `TicketCommentRequest` | `content`、`internal` | 正文必填 ≤2000；`internal` 默认 false |
| `TicketFeedbackRequest` | `score`、`comment` | 评分 1-5；评价 ≤500 |

### 7.3 管理端

## 8. 响应 VO 一览

所有 VO 位于 `com.servicedesk.vo`，使用 `@Builder` + `final` 字段，**不暴露实体、不包含密码哈希**。

| VO | 关键字段 |
| --- | --- |
| `LoginVO` | `token`、`expiresIn`、`user`（`UserVO`） |
| `UserVO` | `id`、`username`、`displayName`、`role`、`teamId`/`teamName`、`customerId`/`customerName`、`phone`、`email`、`status` |
| `TeamVO` | `id`、`name`、`supervisorId`/`supervisorName`、`memberCount`、`description` |
| `CustomerVO` | `id`、`name`、`contact`、`phone`、`address`、`level`、`remark` |
| `DeviceVO` | `id`、`customerId`/`customerName`、`model`、`serialNo`、`purchaseDate`、`warrantyEnd`、`warrantyStatus`（实时计算）、`location`、`status` |
| `TicketListItemVO` | `id`、`ticketNo`、`title`、`category`、`urgency`、`status`、`customerName`、`deviceModel`、`assigneeName`、`teamName`、`slaRemainingMinutes`、`slaBreached`、`createdAt` |
| `TicketDetailVO` | 主字段 + `customer` / `device` / `reporter` / `assignee` / `team` 嵌套 record + `sla` + `ai`（目前恒 null）+ `attachments` + `version` |
| `TicketEventVO` | `id`、`type`、`fromStatus`、`toStatus`、`operatorId`/`operatorName`/`operatorRole`、`content`、`internal`、`metadata`、`createdAt` |


## 9. 公共层的使用建议

1. Controller 一律返回 `Result.success(...)`，不要在 Controller 里 try/catch；
2. 业务失败直接抛 `BusinessException`，让全局处理器统一输出；
3. 查询列表用 `PageResult.from(...)`，不要手工拼 total；
4. 新代码取时间注入 `Clock`；
5. 新代码取当前用户用 `UserContext.getRequired()`，不要 `get()` 后到处判空。
