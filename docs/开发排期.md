## 1. 交付定义

一个月后交付一个**本地可跑通的全栈闭环 MVP**，不是全部 P0 的完整实现。

验收口径：

1. 浏览器里能走完：登录 → 建单（AI 预填分类定级）→ 主管派单 → 工程师接单 → 看知识推荐并写处理记录 → 解决 → 报修人验收关闭。
2. P0 主干接口可被前端真实调用，无 mock 残留。
3. 权限四档生效：报修人只看自己、工程师只看指派、主管只看本团队、管理员全量，越权统一 404。
4. `mvn test` 全绿，状态机 / 数据范围 / 乐观锁三处有矩阵或参数化测试。
5. 演示脚本在 15 分钟内跑通（见第 6 节）。

不在交付定义内：部署上线、多租户、流式输出、任何 P1 功能。

## 2. 节奏约定（与开发流程绑定）

| 项 | 约定 |
| --- | --- |
| 投入 | 每天 6 小时以上有效开发，周末照常推进 |
| 切片 | 每天 2-3 个切片，单切片 ≤ 200 行生产代码（不含测试） |
| 单测 | 每个切片写完立即补测并运行，**测试不绿不进入下一片** |
| 确认 | 每个切片交你 review，你确认通过后才开下一片；有意见先改到过 |
| 提交 | 一个切片一个 commit，信息用 `feat/fix/test` 前缀 + 模块名 |
| 注释 | 类/方法/常量 Javadoc 齐全，按 `docs/编码规范.md` 第 8 节执行 |
| 单测门槛 | Service 层每个公开方法至少覆盖「正常 + 一个业务异常」；状态迁移、数据范围、乐观锁必须穷举 |

排期已把「等你确认」的时间算进去。若某天连续两片被打回，当天不再加新切片，顺延到次日缓冲。

## 6. 最终验收

演示脚本（对应产品文档 9.3，按降级调整）：

1. 报修人提交「空压机异响」，AI 分类为硬件故障 / P1 并给出一句话摘要。
2. 主管在工作台看到 SLA 倒计时，把工单派给张工。
3. 张工接单，右侧出现 3 条知识推荐，点开引用，写处理记录。
4. 张工解决，报修人验收，工单关闭，时间线完整可查。
5. 主管查看超时工单（被动计算的红字标记）与团队负载。
6. Agent 抽屉提问「查 SN-2024-001 过保没」，返回设备信息与保修状态（只读，无写操作）。

第 5、6 步为降级版，NL2SQL 与 Agent 写操作以口述说明后续规划。
