## 1. 注释规范（核心约定）

> **所有类、所有方法、所有常量字段（static final）必须有注释；普通成员变量若命名不足以见名知意，也必须加注释。**

### 1.1 必须加注释的元素

| 元素 | 是否必须 | 形式 |
| --- | --- | --- |
| 类 / 接口 / 枚举 | 必须 | Javadoc：说明职责、所属层、关键约束 |
| 方法 | 必须 | Javadoc：入参、返回值、抛出异常、幂等性与事务边界 |
| 常量字段（static final） | 必须 | 逐个行上注释，说明取值含义与来源 |
| 普通成员变量 | 命名不足以见名知意时必须 | 行上注释或字段 Javadoc |

### 1.2 各类注释写什么

- **类**：这个类负责什么、属于哪一层、有哪些不可违反的约束。例：`TicketEventWriter` —— 工单时间线唯一写入口，保证只追加不修改。
- **方法**：入参的业务含义、返回值的语义、会抛出的业务异常（404 越权或不存在、409 状态或版本冲突）、是否幂等、是否开启事务。
- **常量**：取值范围与业务含义，不重复变量名本身。例：`ESCALATED` 不是状态，是标记加事件。
- **字段**：字段名无法表达含义时补注释。例：`metadata.internal` 表示内部备注标记；`pausedAt` 表示本次暂停的开始时间。

### 1.3 格式与禁忌

- 类、方法、字段用 Javadoc；行内说明用单行注释。
- 禁止空注释（例如复述代码的「设置参数」这类注释）。
- 禁止没有责任人与原因的 TODO。
- 注释与代码同步修改；优先解释为什么这样设计，而不是复述做了什么。
- 枚举的每个值单独一行注释。

## 2. 其他约定

| 项 | 约定 |
| --- | --- |
| 分层依赖 | 见目录结构文档第 3 节：Controller 不写业务判断；数据范围只在 `domain/ticket/TicketScope` 拼装；domain 层不依赖 Spring Bean；ai 层不直接访问 Mapper |
| 枚举 | 一律存字符串，不存魔法数字；每个值单独注释 |
| 错误处理 | 业务异常抛 `BizException`，由 `GlobalExceptionHandler` 统一转 { code, message, data }；越权与不存在统一 404 |
| 时间 | 统一用 `LocalDateTime`；接口输出 ISO 8601 `yyyy-MM-dd`T`HH:mm:ss` + `Asia/Shanghai` |
| 事务 | 状态迁移、SLA 时间戳维护、事件写入必须在同一事务内 |
| 幂等 | 工单号生成、Agent 写操作、SLA 超时升级均需幂等 |
| 文档同步 | 角色、状态、枚举、表名、接口路径改动必须同步三份契约文档 |
